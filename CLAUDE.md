## ТЗ

Стек: React + Vite (JavaScript), @supabase/supabase-js, без UI-библиотек, свой CSS. Интерфейс на русском. Хостинг: GitHub Pages (статика, репозиторий публичный).

Суть: я веду свои задачи (Программирование, Словенский, Английский, Зал и любые свои) и каждый день отмечаю, выполнил или нет. Главный экран похож на GitHub contributions: годовая сетка квадратиков по каждой задаче.

1. Задачи: добавить / переименовать / удалить (с подтверждением прямо в интерфейсе, без confirm()) / поменять порядок. У каждой свой цвет из палитры 8 цветов (без красного, красный = пропуск). Если задач нет — кнопка "Добавить стартовый набор" с 4 задачами выше.
2. Отметки: только "сделано / не сделано". Прошедший день без отметки автоматически = пропуск. Пропуски считаются только с даты старта задачи — habit.start_date (при создании = локальная дата создания; на экране "Задачи" её можно сдвинуть вручную полем "Начало", input type="date", max = сегодня; сохранение через update, оптимистично, с откатом при ошибке). Самая ранняя отметка старт НЕ сдвигает: отметки до start_date показываются как "сделано" и учитываются в отметках и сериях, а дни до start_date без отметки — серые ("до старта"), не красные. Будущие дни отмечать нельзя, прошлые — можно.
3. Экран "Сегодня": список задач с большой кнопкой-галочкой, текущая серия и рекорд, мини-полоска последних 7 дней (кликабельная), итог "N из M сделано" с кольцом прогресса.
4. Экран "Год": переключатель года, для каждой задачи карточка с сеткой 53 недели × 7 дней (неделя с понедельника), подписи месяцев и дней недели, счётчик выполненных дней, число пропусков, легенда. Цвета: сделано = цвет задачи, пропуск = красный, сегодня не отмечено = прозрачный с обводкой, будущее/до старта = серый. Клик по ячейке переключает отметку. На телефоне сетка скроллится горизонтально внутри карточки.
5. Экран "Статистика": период неделя / месяц / год с листанием назад-вперёд (вперёд дальше текущего нельзя). Плитки: % выполнения, отметок X / Y, "идеальные дни" (все задачи сделаны). Столбиковая диаграмма по дням (для года — по месяцам), полный столбик ярче. Таблица по задачам: полоса и %, дни X/Y, текущая серия, рекорд за всё время. Сегодняшний день считается в "возможные" только если уже отмечен. "Возможные" дни (и счётчик пропусков на экране "Год") считаются только начиная с start_date; отметка до start_date — это день, который сделан, но в "возможные" не входит (см. план).
6. Даты: везде локальные даты в формате YYYY-MM-DD, никаких toISOString() (сдвиг из-за UTC). "Сегодня" должно обновляться после полуночи без перезагрузки.
7. Дизайн: делать строго по утверждённому макету design/design-mockup.html — те же цвета (CSS-переменные из :root и тёмной темы), шрифты (Onest + JetBrains Mono), отступы, скругления, вид карточек, сетки, кнопок-галочек и статистики. Макет статический (вкладки на радиокнопках) — в приложении сделать нормальные React-компоненты, но визуально 1:1. Верхнюю пунктирную полосу "Макет · примерные данные" в приложение не переносить. Данные в макете — пример, в приложении всё из Supabase. Тёмная/светлая тема по prefers-color-scheme, адаптив под телефон.

## Безопасность (обязательно)
- Вход через Supabase Auth по email + пароль. Регистрации в интерфейсе нет (в Supabase я её отключу, пользователя создам вручную).
- Без входа — только экран логина, никаких данных.
- Таблицы habits (id uuid, user_id default auth.uid(), name, color, position, start_date, created_at) и checkins (habit_id, user_id default auth.uid(), day date, PK (habit_id, day)). ON DELETE CASCADE.
- Включить Row Level Security на обеих таблицах, политики: пользователь видит и меняет только строки, где user_id = auth.uid(); при вставке checkin проверять, что habit принадлежит этому же пользователю. Отозвать права у роли anon.
- SQL положить в supabase/schema.sql.
- В коде и репозитории никаких секретов. URL и publishable(anon)-ключ берутся из переменных окружения VITE_SUPABASE_URL и VITE_SUPABASE_KEY. .env в .gitignore, рядом .env.example. service_role ключ нигде не использовать.
- Если переменные не заданы — показать понятный экран "не настроено", а не белый экран.

## План реализации (заметки для работы)

- Структура: `src/lib/` (supabase-клиент, даты, расчёты), `src/components/` (Header, Login, NotConfigured, общие), `src/screens/` (Today, Year, Stats, Habits), `src/styles.css` — CSS перенесён из макета 1:1 (без `.mock-bar` и радиокнопок).
- Вкладки шапки (как в макете): Сегодня / Год / Статистика / Задачи. Экран «Задачи» — управление задачами (п.1 ТЗ).
- Даты: только хелперы из `src/lib/dates.js` (`toKey(date)` → `YYYY-MM-DD` по локальному времени, парсинг ключа в локальную дату). `toISOString()` не использовать.
- «Сегодня»: хук `useToday()` — таймер до следующей локальной полуночи + проверка при `visibilitychange`/`focus`.
- Данные: habits + checkins (постранично через `range()` по 1000). Отметки в `Map<habitId, Set<dayKey>>`.
- Оптимистичные отметки: последовательная очередь промисов на ключ `habitId|day`; при ошибке — откат к состоянию сервера и тост.
- Старт задачи — только `habit.start_date`. Статус дня: будущее → future; есть отметка → done (даже до старта); до старта → none (серый); сегодня без отметки → pending; иначе → miss.
- Отметки: upsert с `ignoreDuplicates: true` (у checkins нет UPDATE), снятие — delete. start_date при создании — локальная дата явно.
- Фокус: рамка только по `:focus-visible`. Кнопкам-переключателям (вкладки, цвета, галочки, мини-квадратики, ячейки сетки, листание) ставить `onMouseDown={noMouseFocus}` из `src/lib/noMouseFocus.js`.
- Год: раскладка `yearLayout(year)` (`src/lib/yearGrid.js`) считается через useMemo по году, общая для всех карточек; карточки в `memo`. Листание: назад — не раньше min(самый ранний год среди start_date и отметок, текущий год − 1), вперёд — до `MAX_YEAR` = 2030 включительно (константа в `src/lib/yearGrid.js`; если текущий год уже больше — до текущего). Для лет без данных сетка серая ("до старта" / "ещё не наступил"), счётчики 0. Выключенные стрелки — opacity .35. (На "Статистике" листание по своим правилам, см. ниже.) Пропуски в карточке — дни от start_date до вчера без отметки.
- Цвета задач хранятся ключами палитры: green, blue, violet, amber, teal, pink, orange, slate → `var(--h-<key>)`.

## Статистика — правила расчётов (реализация: `src/lib/stats.js`, проверка: `npm run check`)

1. Периоды: неделя (пн–вс), месяц, год. Листание назад не раньше самого раннего года из данных (min из start_date и отметок; без поправки «текущий − 1», как на "Год"), вперёд не дальше текущего периода.
2. Для задачи "возможные" дни = дни периода от max(start_date, начало периода) до min(конец периода, вчера), плюс сегодня — только если сегодня отмечено.
3. "Сделано" для % = отметки внутри этих возможных дней. Отметки до start_date в % НЕ входят (иначе может быть больше 100%), но входят в плитку "Отметок" и в серии.
4. Плитка "Выполнение" = сумма сделанного / сумма возможных по всем задачам. Если возможных 0 — показывать "—", а не NaN.
5. "Идеальный день" = день, где все задачи, активные в этот день (start_date <= день), отмечены. Считаются дни периода до вчера, сегодня — только если уже всё отмечено. Дни без активных задач не считаются.
6. Диаграмма: неделя/месяц — столбик на каждый день (доля выполненных активных задач), год — 12 столбиков по месяцам (% выполнения месяца). Будущие дни/месяцы — пустые, полный 100% столбик ярче, как в макете.
7. Таблица по задачам: полоса и %, дни X/Y, текущая серия, рекорд за всё время.
8. Граничные случаи (задача стартовала посреди периода, отметки до старта, пустой период, период в будущем) проверяются скриптом `scripts/check-stats.mjs`.
